# Death Combat

3D-файтинг в духе Mortal Kombat 11 на C++20 и OpenGL 4.6, без игрового движка. Финальный проект.

- **Архитектура** (читать первой): [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)
- Продукт и рамки: [PRODUCT.md](PRODUCT.md)
- Старый 2D-прототип (только справка, не собирается): [prototype/main.cpp](prototype/main.cpp)

## Запуск в Visual Studio

1. Установите **Visual Studio 2022 (17.8+) или новее** с нагрузкой «Разработка классических приложений на C++». В неё уже входят CMake, Ninja и vcpkg.
2. Один раз на машине включите Git LFS (бинарные ассеты лежат в LFS):
   ```bash
   git lfs install
   ```
3. **Файл → Открыть → Папка…** и выберите папку репозитория. Visual Studio сама найдёт `CMakePresets.json`.
4. В списке конфигураций вверху выберите **Debug**. Первая настройка CMake скачивает и собирает библиотеки через vcpkg: 5–15 минут, потом всё берётся из кеша.
5. В списке целей запуска выберите **DeathCombat.exe** и нажмите **F5**.

Тесты: **Тест → Обозреватель тестов** (doctest через CTest).

Если CMake пишет, что не найден `vcpkg.cmake`, значит, переменная `VCPKG_ROOT` пуста: доустановите компонент vcpkg в Visual Studio Installer или склонируйте vcpkg и пропишите `VCPKG_ROOT` в переменные среды.

### Из командной строки

В «Developer PowerShell for VS»:

```bash
cmake --preset debug
```

```bash
cmake --build --preset debug
```

```bash
ctest --preset debug
```

## Что уже работает (каркас)

Это «ходячий скелет»: каждая система архитектуры на месте, данные проходят через весь конвейер, но содержимое ещё предстоит написать.

- Окно OpenGL 4.6 core с GL debug output, Dear ImGui с кириллицей.
- Главный цикл: фиксированный тик 60 Гц + интерполяция для рендера (§3).
- Детерминированная симуляция: интро раунда, ходьба, присед, прыжок, пушбоксы, стены, таймер, раунды (§4).
- Ввод: клавиатура и геймпады, SOCD-очистка; ИИ — виртуальный контроллер (§5, §6).
- Данные бойцов и приёмов из JSON с понятными ошибками (§4.5).
- Камера боя, отладочная отрисовка боксов, временный HUD в ImGui (§7, §10).
- Тесты: детерминизм, ходьба, пушбоксы, прыжок, таймер, SOCD, ИИ, загрузка данных.

Управление в каркасе: **P1** — `W A S D` (ходьба, прыжок, присед), P2 — ИИ. `F1` — боксы, `F2` — пауза, `F3` — шаг на один тик, `Esc` — выход.

## Как работать с кодом

- **Каждый `TODO(§N)` в коде ссылается на раздел [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).** Поиск по `TODO(` даёт полный список работ, дорожная карта по неделям — в §14.
- Новый `.cpp` или `.h` кладите в папку модуля: CMake подхватит его сам при следующей сборке.
- Подключение — от корня `engine/` или `game/`: `#include "sim/match_state.h"`, `#include "gfx/renderer.h"`.
- Нельзя: OpenGL, звук или часы в `game/sim`; изменение `MatchState` из ИИ или представления; `std::vector` и указатели внутри `MatchState`.
- Стандарты кода — §12.3 (C++ Core Guidelines). Форматирование — `.clang-format` (в Visual Studio: `Ctrl+K, Ctrl+D`).

## Структура

```
engine/        движок — ничего не знает о файтинге
  core/        лог, assert, ошибки, файлы, StaticVector, Pcg32, хэндлы
  platform/    окно GLFW + OpenGL 4.6, окно ошибки
  gfx/         RAII-обёртки GL (DSA), шейдеры, рендер, отладочные линии, ImGui
  anim/        скелет, клипы, позы, плеер анимаций, time-warp
  audio/       miniaudio
  assets/      JSON, изображения (stb), glTF (cgltf), AssetManager
  input/       клавиатура и геймпады
  ui/          виртуальный холст 1920×1080, функции плавности
game/          файтинг
  sim/         детерминированная симуляция боя (без GL!)
  data/        загрузка правил, бойцов и приёмов из JSON
  ai/          ИИ — виртуальный контроллер
  controls/    раскладки → InputFrame
  presentation/ камера, вид бойца, VFX, звук боя, кинематики
  hud/         HUD
  scenes/      сцены: матч (меню — по дорожной карте)
  app/         окно, главный цикл, стек сцен
assets/        шейдеры, правила, бойцы, приёмы (бинарное — через Git LFS)
tests/         doctest
third_party/   GLAD 2 (OpenGL 4.6 core)
```
